# Сборка 105 — как собрать игру для шлема: для сборщика, оператора и Claude

**105** — линия сборки для шлема весом около 105 МБ. На 2026-10-02 это `headset-latest` из `main`: 105 021 985 Б. Всё, что здесь написано, проверено командами в CI или на дев-сервере. Числа взяты из вывода ворот, не на глаз (ТАБУ №0.011 п. 6).

**Конституция:** ФОРМА (вся сборка как она есть: её код и её слово) → ДЕЙСТВИЕ (собрать её в одном месте из одного источника, у каждого файла ссылка и хэш) → ЦЕЛЬ (кто собирает, проверяет или решает, находит каждую часть игры, и сборку можно повторить).

| [../.github/workflows/build-105.yml](../.github/workflows/build-105.yml) | YAML сборки папки 105: проверяет указатель, собирает `ludus-105.zip` и на `main` кладёт его в релиз `headset-latest` рядом с APK |

**Почему в репозитории нет второй копии кода.** Копия рядом с исходниками устареет с первым же коммитом. Все ворота, которые обходят репозиторий, увидят каждый файл дважды, а это нарушает правило одного источника (ТАБУ №0.35 п. 12).

Полная папка — `ludus-105.zip`: внутри `105/` с каждым файлом кода и каждым документом, плюс `MANIFEST.json` с путём, размером и SHA-256 каждого файла и коммитом. Её собирает [build-105](../.github/workflows/build-105.yml) при каждом запуске, а локально — команда:

```sh
python3 105/make_105.py --bundle build/ludus-105.zip
```

## 2. Для сборщика: CI и локальная сборка

### 2.1. Сборки в CI (GitHub Actions)

| Workflow | Что делает | Когда запускается |
|---|---|---|
| [godot.yml](../.github/workflows/godot.yml) «Godot headset build» | задание `test`: фикстуры, ворота бюджетов, тесты Godot, кадры, замеры сцен, веб-экспорт. Задание `android`: APK для Quest | push в `main` и `claude/**`, pull request, вручную |
| [godot-engine.yml](../.github/workflows/godot-engine.yml) «Godot engine template (headset)» | свой шаблон движка Godot 4.7.1 без неиспользуемых модулей: две библиотеки и `android_source.zip`, кэш по хэшу профиля | pull request и push в `main` при смене `scripts/godot/engine/**`, вручную |
| [build-105.yml](../.github/workflows/build-105.yml) «Build 105» | указатель папки 105 и архив `ludus-105.zip` | push в `main`, pull request, вручную |
| [raw-asset-intake.yml](../.github/workflows/raw-asset-intake.yml) | раннер сырья: 35 %, 12 вариаций, реестр лицензий | вручную, pull request |
| [raw-osint-cycle.yml](../.github/workflows/raw-osint-cycle.yml) | ежечасный раннер дефицитов по 99 репо | каждый час в :17 UTC |

**Как запустить вручную:** GitHub → Actions → нужный workflow → «Run workflow» → ветка.

**Шаги задания `android`** ([godot.yml](../.github/workflows/godot.yml), по порядку):
1. JDK 17 (Temurin), Godot 4.7.1 и шаблоны Android — `scripts/godot/ci_setup.sh android`.
2. **Свой шаблон движка.** Он берётся из кэша `engine-android-4.7.1-stable-<хэш>`. Если его нет, берётся стоковый, и на странице проверки появляется заметка «Engine template».
3. Плагин вендоров Meta OpenXR `5.1.0-stable` (MIT) — скачивается, в репозиторий не коммитится.
4. Ключ подписи: секрет `LUDUS_DEBUG_KEYSTORE_B64`, а если он не читается — ключ из кэша. Источник ключа и отпечаток SHA-256 видны в заметке «APK signing key».
5. Android SDK: `platform-tools`, `build-tools;34.0.0`, `platforms;android-34`.
6. `version/code` = номер прогона. Каждая сборка встаёт поверх прежней (ТАБУ №0.01 п. 3).
7. Экспорт: `godot --headless --path . --install-android-build-template --export-debug "Meta Quest" ../build/godot/ludus-dive-quest.apk` (Gradle, min SDK 29, target SDK 34, только arm64-v8a, пакет `org.ludus.dive`).
8. Проверка манифеста: записи OpenXR и `com.oculus` на месте.
9. Ворота APK: `python3 scripts/godot/check_budgets.py --apk build/godot/ludus-dive-quest.apk`.
10. На `main` — релиз `headset-latest`: APK и его SHA-256.

**Шаги `godot-engine.yml`** (свой движок; решение — [ENGINE_BUILD](../docs/decisions/ENGINE_BUILD_2026-10-02.md), фазы — [HLD_ENGINE_BUILD](../docs/HLD_ENGINE_BUILD_2026-10-02.md)):
1. `python3 scripts/godot/engine/profile.py --check` — вырезанное игрой не используется.
2. Исходники Godot `4.7.1-stable` (`git clone --depth 1`), затем Swappy (`python misc/scripts/install_swappy_android.py`).
3. `scons` для `template_debug` и `template_release`. Строку аргументов выдаёт `profile.py --scons android <target>`: `optimize=size lto=thin production=yes`, профиль [ludus.gdbuild](../scripts/godot/engine/ludus.gdbuild) и выключенные модули. NDK `29.0.14206865` ставит сам SCons.
4. `./gradlew generateGodotTemplates`, на выходе `bin/android_source.zip`.
5. Размеры `libgodot_android.so`, SHA-256 архива, кэш и артефакт.

Замер 2026-10-02, прогон 37024269156: отладочная библиотека 76 177 376 → 53 289 240 Б (−30,0 %), выпускная 71 110 440 → 52 719 672 Б (−25,9 %).

> Кэш GitHub виден только той ссылке, что его сохранила, и `main`. Поэтому шаблон собирается на pull request и на `main`, а не на push в ветку. Первая проба положила его туда, где сборка APK его не ищет.

### 2.2. Локальная сборка (Linux, дев-сервер)

Нужно: Godot 4.7.1 (редактор Linux), шаблоны экспорта 4.7.1, JDK 17, Android SDK 34 с `build-tools;34.0.0`, Python 3.10+, Node 20+.

```sh
# Тесты и ворота, как в задании test
python3 scripts/godot/check_budgets.py --tree
python3 scripts/godot/engine/profile.py --check
python3 scripts/decisions/engine_build_choice.py --check
python3 scripts/decisions/size_strategy_choice.py --check
node --test tests/*.test.js
cd godot
godot --headless --path . --import
godot --headless --path . -s res://tests/run_hub_tests.gd
godot --headless --path . -s res://tests/run_tests.gd
xvfb-run -a -s "-screen 0 1280x720x24" godot --path . \
  --rendering-driver opengl3 -s res://tools/measure_budgets.gd \
  -- --scene=hub --check            # и dive, witness
xvfb-run -a -s "-screen 0 1280x720x24" godot --path . \
  --rendering-driver opengl3 -s res://tools/measure_locations.gd -- --check

# APK (нужны SDK и ключ androiddebugkey / android)
godot --headless --path . --install-android-build-template \
  --export-debug "Meta Quest" ../build/godot/ludus-dive-quest.apk
python3 ../scripts/godot/check_budgets.py --apk ../build/godot/ludus-dive-quest.apk
```

**Свой движок локально** (проверено на дев-сервере 2026-10-02):
- 4 ядра, около 10 минут на Linux-шаблон;
- около 1,5 ГБ на объектные файлы;
- 430 МБ на исходники.

```sh
pip install scons
git clone --depth 1 --branch 4.7.1-stable https://github.com/godotengine/godot.git
cd godot
scons -j4 $(python3 ../ludus/scripts/godot/engine/profile.py --scons linuxbsd template_debug)
# Для проверки игры на этом шаблоне нужна подмена пути к проекту:
scons -j4 $(python3 ../ludus/scripts/godot/engine/profile.py --scons linuxbsd template_debug) \
  disable_path_overrides=no
bin/godot.linuxbsd.template_debug.x86_64.llvm --headless --path ../ludus/godot \
  -s res://tests/run_hub_tests.gd
```

Итог проверки на своём движке:
- 26 наборов тестов хаба и `run_tests` — 0 ошибок;
- все 99 мест в бюджете;
- хаб, погружение и свидетель — 97, 96 и 85 вызовов отрисовки;
- скорость та же: 8 мест за 23,2 с против 23,4 с на стоковом движке.

## 3. Для оператора: поставить APK в Quest 3S и проверить

### 3.1. Взять APK

1. Откройте релиз **headset-latest** репозитория (GitHub → Releases). Это сборка из `main`.
2. Скачайте `ludus-dive-quest.apk` и файл с SHA-256 рядом с ним.
3. Сверьте контрольную сумму: `sha256sum ludus-dive-quest.apk` (Linux/macOS) или `certutil -hashfile ludus-dive-quest.apk SHA256` (Windows).
4. Сборка ветки (до мёржа): GitHub → Actions → прогон «Godot headset build» → артефакт `ludus-dive-quest-apk`.

### 3.2. Поставить в шлем

1. В приложении Meta Horizon на телефоне включите **режим разработчика** для своего Quest 3S.
2. Подключите шлем кабелем USB-C и наденьте его: разрешите «Отладку по USB».
3. Поставьте APK одним из способов:
   - **adb:** `adb install -r ludus-dive-quest.apk` (`-r` ставит поверх, сохранения остаются);
   - **Meta Quest Developer Hub:** перетащите APK в окно устройства;
   - **SideQuest:** кнопка «Install APK».
4. В шлеме: Библиотека → фильтр «Неизвестные источники» → **Ludus**.

> Сборка встаёт поверх прежней, пока ключ подписи тот же. Отпечаток ключа — в заметке «APK signing key» на странице проверки `android`, сейчас `1F:50:66:98:…:D0:F6`. Если когда-нибудь появится `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, ключ сменился: нужна одна переустановка (`adb uninstall org.ludus.dive`), и сохранения пропадут. Подробности — [APK_REQUIREMENTS, «Ключ подписи»](../docs/APK_REQUIREMENTS.md).

### 3.3. Пакет английских голосов (когда будут записи)

Пакет `voice-en.pck` кладётся рядом с игрой, и она подключает его сама при запуске ([data_packs.gd](../godot/scripts/data_packs.gd)):

```sh
adb shell mkdir -p /sdcard/Android/obb/org.ludus.dive
adb push main.<versionCode>.org.ludus.dive.obb /sdcard/Android/obb/org.ludus.dive/
```

Без пакета игра идёт на тексте. Как устроен OBB и зачем он нужен — [ГОСТ-описание](../docs/gost/ОП_OBB_ПАКЕТ_РАСШИРЕНИЯ_ГОСТ_19.402.md).

### 3.4. Что проверить в шлеме

По [STORY_12_HEADSET_TEST](../docs/STORY_12_HEADSET_TEST_2026-10-02.md):
- 12 сюжетов через доску «Проверка: открыть сюжет…»;
- люди сюжетов и их разговоры;
- буря и хаптика;
- переход к аппарату без рывка.

Замеры, которые возможны только в шлеме (OVR Metrics Tool): кадр у стапеля, пик скрипта на 60 м, длина затемнения, нагрев, пик памяти по PSS против предела 5,75 ГиБ. Что ждёт вашего решения — [долг оператора](../docs/OPERATOR_DEBT_2026-10-02.md).

«Проверено в шлеме» говорите только вы (ТАБУ №0.02 п. 4).

## 4. Для Claude: порядок работы и ворота

Правила — [CLAUDE.md](../CLAUDE.md). Это короткая выжимка для сборки.

1. **Сначала HLD по фазам** (ТАБУ №0.02), строка Конституции у каждого решения.
2. **Итог — в APK** (ТАБУ №0.01). Красное задание `android` чинится первым.
3. **Ревизор лимитов** (ТАБУ №0.011): `check_budgets.py --tree`, замеры сцен и МД-ревью в [docs/review](../docs/review/). Прирост APK пишется в описание PR.
4. **Крупные модули — только через `ModuleLoader`** (ТАБУ №0.014).
5. **Свой движок:** вырезать только то, что `profile.py --check` доказывает неиспользуемым. Новая механика, которой нужна вырезанная часть, делает CI красным. Тогда часть возвращается в профиль, и шаблон пересобирается.
6. **Отгрузка страсти раннером.** После неё пересобрать все копии: `node tests/ludus-antagonist-factory.test.js --write`, `python3 scripts/build_rights_manifest.py`, `node scripts/godot/export_antagonist_manifest.js`, `node scripts/godot/make_passion_fixture.js`, скопировать 12 спрайтов в `godot/art/derived/DEF-001/` (урок цикла 84).
7. **Указатель 105:** после добавления, удаления или переименования файла кода или документа запустить `python3 105/make_105.py`, иначе `build-105` покраснеет.
8. **Не останавливать процессы через `pkill -f` с шаблоном,** который совпадает с командой самой оболочки: это убивает оболочку (код 144). Останавливать по PID через `ps`.
9. **Коммиты:** трейлеры `Co-Authored-By` и `Claude-Session`. Ветка `claude/gracious-clarke-36w4kh`, в `main` — только через PR.
