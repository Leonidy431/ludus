# Доставка игры и пакетов на шлем через Git и GitHub Releases

**Описание программы (по ГОСТ 19.402-78)** · Ludus, сборка для Meta Quest 3S · 2026-10-02

Правила: ТАБУ №0.01 (APK — итог задачи, ставится поверх прежнего, Release `headset-latest`) и ТАБУ №0.018 (малая установка и подкачка). Выбор способа — `scripts/decisions/stream_choice.py` (пул 780, 32 параметра). HLD — `docs/HLD_PACKS_STREAM_2026-10-02.md`.

---

## 1. Общие сведения

1.1. **Обозначение:** подсистема доставки Ludus — Git-репозиторий `Leonidy431/ludus`, GitHub Actions, GitHub Releases, автозагрузки `DataPacks` и `PackFetch` в игре.

1.2. **Программное обеспечение:**
- Git 2.x;
- GitHub (репозиторий, Actions, Releases);
- Godot 4.7.1 (свой шаблон, `scripts/godot/engine/`);
- Python 3.11 (скрипты сборки и проверок);
- на шлеме — Android/Horizon OS, приложение `org.ludus.dive`.

1.3. **Языки:** GDScript (игра), Python (сборка, проверки), YAML (workflow), JSON (манифесты).

## 2. Функциональное назначение

Подсистема доставляет на шлем две вещи — по образцу The Pandora Directive (жёсткий диск и CD):

| | Что | Предел | Откуда шлем берёт |
|---|---|---|---|
| **«Жёсткий диск» — APK** | движок, логика, интерфейс, данные, прокси, первая серия целиком | 128 МиБ (наш бюджет, `scripts/godot/apk-budgets.json`) | Release `headset-latest`, ставится через Meta Quest Developer Hub, SideQuest или `adb install -r`; с магазином — из магазина |
| **«CD» — пакеты `.pck`** | голоса, музыка, пререндеры сверх первой серии, финальные модели, серии 2+ | файл Release до 2 ГиБ; пакет держим ≤ 500 МБ | игра сама качает фоном с Release по манифесту `godot/data/packs.json` |

Игра стартует и проходится без сети. Пакеты добавляют голос и новые серии.

## 3. Описание логической структуры

### 3.1. Git — источник истины

- Код, данные, манифесты, исходники пакетов и скрипты сборки лежат в Git. Бинарные артефакты (APK, `.pck`) в Git **не кладутся**, они лежат в Releases. Так репозиторий не раздувается, а артефакт привязан к коммиту.
- Работа идёт на ветках `claude/*`, в `main` — только через PR (дайджест п. 7).
- Каждый артефакт несёт коммит, из которого собран: `MANIFEST.json` папки 105 и `version/code` APK.

### 3.2. Сборка APK (`.github/workflows/godot.yml`, задание `android`)

1. Checkout → ворота бюджетов (`check_budgets.py --tree/--pck`) → экспорт Godot для Android (OpenXR, плагин Meta).
2. Свой шаблон движка берётся из кэша (`godot-engine.yml`), иначе сток с пометкой в аннотации.
3. Подпись постоянным ключом (секрет `LUDUS_DEBUG_KEYSTORE_B64`, иначе кэшированный ключ). Отпечаток публикуется аннотацией. Номер версии растёт с каждой сборкой, поэтому APK ставится поверх прежнего с сохранениями.
4. `check_budgets.py --apk` по готовому APK. Превышение — красная сборка.
5. Из `main`: APK и `.sha256` выкладываются в Release `headset-latest`. Из веток — артефакт прогона.

### 3.3. Сборка и публикация пакета (фаза K2, план)

1. Исходники пакета — в Git под `godot/packs/<id>/` (вне экспорта APK, фильтр `exclude_filter`).
2. Workflow `packs.yml` (по изменению `godot/packs/**`):
   - собирает `<id>.pck` (`godot --export-pack` с пресетом «pack-<id>», чтобы картинки и звук прошли импорт, как в APK);
   - считает размер и SHA-256;
   - выкладывает `<id>-v<N>.pck` в Release `packs-<id>-v<N>`.
3. Строка манифеста `godot/data/packs.json` (`id`, `file`, `bytes`, `sha256`) коммитится PR. Манифест едет внутри APK, поэтому новый пакет становится виден игре со следующим APK. Подменить пакет на чужой без нового APK нельзя.
4. Версия пакета неизменна. Новая версия — новый файл и новый тег. Откат — прежняя строка манифеста: старый Release не удаляется (журнал не уничтожается, ТАБУ №0.25 п. 5).

### 3.4. Загрузка на шлеме (`godot/scripts/pack_fetch.gd`, автозагрузка `PackFetch`)

1. Сцена говорит `PackFetch.want(id)`, когда игрок идёт к месту, где пакет нужен: пристань, доска сюжетов, вход в серию 2 (ТАБУ №0.014).
2. `HTTPRequest` в отдельном потоке пишет `GET <base><file>` в `user://packs/<id>.pck.part`. Заголовков с данными игрока нет.
3. Сверяются размер и SHA-256 (`HashingContext`, кусками по 1 МиБ). Совпало — файл переименовывается в `<id>.pck` и монтируется `DataPacks.mount` (`ProjectSettings.load_resource_pack(path, false)`: пакет **не заменяет** файлы игры). Не совпало — файл удаляется, статус `failed: checksum`.
4. Нет сети — статус `failed: http`, игра идёт без пакета. При следующем запуске то, что уже лежит и сходится, сразу считается готовым.

### 3.5. Магазин (фаза K5)

С листингом в Meta Store тот же `.pck` может прийти как OBB (`/sdcard/Android/obb/org.ludus.dive/main.<versionCode>.org.ludus.dive.obb`, `DataPacks.pick_obb`) или как Asset File платформы. Формат один, в коде меняется только источник.

## 4. Используемые технические средства

- **Сервер сборки:** GitHub Actions `ubuntu-latest`.
- **Хранилище:** GitHub Releases.
- **Шлем:** Meta Quest 3S, 8 ГБ ОЗУ, лимит приложения 5,75 ГиБ; память пакетов — `user://` приложения, удаляется вместе с приложением.

## 5. Вызов и загрузка

- **Оператор ставит APK:** скачать `ludus-headset.apk` и `.sha256` из Release `headset-latest`, сверить `sha256sum -c`, поставить через `adb install -r ludus-headset.apk` (или Developer Hub, SideQuest). Подробно — `105/СБОРКА.md`.
- **Пакеты:** ничего делать не нужно, игра скачает их сама при сети. Для проверки без сети пакет можно положить вручную: `adb push <id>.pck /sdcard/Android/data/org.ludus.dive/files/packs/`.

## 6. Входные и выходные данные

- **Вход:** коммит в Git; секрет подписи; исходники пакета.
- **Выход:** APK + SHA-256 в `headset-latest`; `.pck` в `packs-<id>-v<N>`; строка манифеста в Git.

## 7. Безопасность и приватность

- **Подмена пакета:** SHA-256 из манифеста внутри подписанного APK. Без нового APK чужой файл не смонтируется.
- **Что уходит в сеть:** только GET публичного файла. GitHub, как любой веб-сервер, видит IP-адрес шлема и заголовок `User-Agent` движка. Это сказано в политике приватности (черновик — `docs/PRIVACY_POLICY_DRAFT.md`, решение — Д-21).
- Исповедь, сохранения, атрибуты, журнал в сеть не уходят никогда (ТАБУ №0.26, №0.35 п. 21). Тест `test_pack_fetch.gd` валит сборку, если в коде подкачки появится идентификатор, сохранение или телеметрия.
