# Проверка 12 сюжетов в Quest 3 — инструкция оператору (2026-10-02)

Это инструкция, а не отчёт о проверке. В шлеме ничего из описанного ещё не проверялось. «Проверено в шлеме» скажет только оператор (ТАБУ №0.02 п. 4).

**Конституция:** ФОРМА (проверяющий в шлеме) → ДЕЙСТВИЕ (открыть любой из 12 сюжетов в отдельном проверочном сохранении) → ЦЕЛЬ (оператор проверяет урок каждого сюжета, не проходя кампанию; в релизной сборке этой двери нет).

## Что это за дверь

Сюжет поздних актов открывается, только когда пройдены прежние акты и пересечены пороги. Поэтому сюжет 90 без входа проверки не достать, не пройдя всю кампанию.

Вход проверки есть только в **отладочной** сборке. APK из CI собирается отладочным экспортом (`--export-debug "Meta Quest"`), поэтому в нём вход есть. В релизной сборке входа нет, и метка проверки там не читается.

Вход проверки пишет **отдельное** сохранение:

| Что | Настоящая игра | Проверка |
|---|---|---|
| двор, миссии, ФОРМА | `user://hub.json` | `user://test-hub.json` |
| погружение, карманы аппарата | `user://dive.json` | `user://test-dive.json` |
| метка «идёт проверка» | — | `user://test-slot` |

Пока проверка идёт, настоящее сохранение не читается и не пишется. После выхода из проверки игра читает его заново, нетронутым.

## 1. Поставить APK

1. Из `main`: GitHub → https://github.com/Leonidy431/ludus/releases/tag/headset-latest → файл `ludus-dive-quest.apk` и рядом `ludus-dive-quest.apk.sha256`.
   - Из ветки: Actions → прогон «Godot headset build» → артефакт `ludus-dive-quest-apk` (хранится 30 дней).
2. Сверить контрольную сумму (только для Release): `sha256sum -c ludus-dive-quest.apk.sha256`.
3. Поставить поверх прежнего, сохранения остаются:
   - `adb install -r ludus-dive-quest.apk`, или
   - Meta Quest Developer Hub → Device Manager → Apps → Add build, или
   - SideQuest → «Install APK file from folder».
4. В шлеме: Библиотека → «Неизвестные источники» → ludus (пакет `org.ludus.dive`).

## 2. Где доска

Игра открывается во дворе обители. Доска дороги стоит на восточной стороне двора: береста на двух дубовых столбах с фонарём, надпись «ДОРОГА ОБИТЕЛИ». Подойдите к ней, пока внизу не появится подсказка «Доска дороги: миссии обители», и нажмите курок правой руки.

Управление на панели: правый стик вверх и вниз выбирает строку, курок правой руки нажимает.

## 3. Открыть сюжет

1. На панели доски, в конце списка, выберите **«Проверка: открыть сюжет…»**.
2. Появится список 12 сюжетов (номер миссии, название, акт). Выберите нужный.
3. Двор откроется заново через затемнение. На доске и на каждой её панели первая строка — **«ПРОВЕРКА — не настоящее сохранение»**.
4. Сюжет уже начат на первом шаге. Доска пишет «Куда идти: …». На её панели строка «Идти: …» ведёт к месту.
5. Шаг делается у сердца места: подойдите к нему, откройте панель, выберите ответ.
   - Если шаг ведёт под воду, после выбора у сердца места аппарат спускается. После подъёма шаг закрывается во дворе, на панели доски («Дальше»).
6. Чтобы взять другой сюжет, снова выберите «Проверка: открыть сюжет…». Проверочное сохранение пишется заново, с первого шага выбранного сюжета.

**Что выбрано в проверочном сохранении.**
- Все миссии до выбранной помечены пройденными (кроме тех, что на переписке у хора).
- Пересечены только пороги, которых требует акт сюжета (`MissionCore.act_lock`).
- Затем миссия начинается обычным `MissionCore.start`: если бы правила дороги её не пустили, вход сказал бы причину.
- **ФОРМА — как у гостя (1 по всем семи).** У каждого шага есть простой ответ, открытый гостю: «отметить место», дело, разговор или поклон, «спускаться по тросу медленно». Глубокие ответы показаны закрытыми с причиной, как их увидит настоящий гость. Поднимать ФОРМУ значило бы спрятать то, что видит гость.

## 5. Выйти из проверки

На любой панели доски, пока идёт проверка, есть строка **«Выйти из проверки»**. Она снимает метку `user://test-slot`, удаляет проверочные файлы и открывает двор заново с настоящим сохранением, тем, что было до проверки.

Если игра закрыта посреди проверки, метка остаётся, и при следующем запуске снова идёт проверка: первая строка доски об этом скажет. Чтобы выйти, нажмите «Выйти из проверки».

## 6. Что отметить при проверке

Для каждого сюжета:
- доска называет нужное место («Куда идти: …»);
- шаг открывается только у сердца своего места, у соседних мест — нет;
- спуск аппарата идёт к вещи шага, шаг закрывается во дворе после подъёма;
- урок сюжета (строка «Урок» выше) читается в репликах и в месте.

Плавность переходов, читаемость панели на 0,9 м, частоту кадров и нагрев подтверждает только шлем (ТАБУ №0.011 п. 6). Замечания пишите одной строкой: номер сюжета, шаг, что не так.

## Как это проверено на компьютере

- `godot/tests/test_story_check.gd` (в `run_hub_tests.gd`) проверяет:
  - для каждого из 12 сюжетов `MissionCore.can_start` пускает его, а `StoryRoute.where` указывает на первое место;
  - вход никогда не пишет `user://hub.json` и `user://dive.json`;
  - при `debug = false` вход скрыт, а метка на диске не включает проверку.
- Кадр доски со списком проверки: `docs/audit/2026-10-02/story-check-board.png`, вид доски с первой строкой проверки: `story-check-board-text.png` (`godot/tools/story_shots.gd --check=…`).
