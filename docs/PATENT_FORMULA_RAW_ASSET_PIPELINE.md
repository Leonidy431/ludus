# Формула изобретения: способ переработки графического сырья для игры

**Статус:** черновик для патентного поверенного. Составлен по коду
`scripts/raw_assets/` и результатам пробного прогона 2026-09-29.
Текст формулы написан на русском в стиле RU-заявки, чтобы юрист видел
его в привычной форме. Описание и доказательства приведены ниже.

---

## Формула

1. Способ получения игровых графических объектов из графического сырья
   сторонних источников, включающий:
   - автоматический отбор источников по перечню репозиториев;
   - частичную загрузку из каждого источника только изображений и
     текстов лицензий;
   - определение лицензии источника и фиксацию ревизии источника;
   - разбиение листов спрайтов на отдельные объекты рекурсивным XY-разрезом
     по прозрачным промежуткам после удаления фона по цвету углового
     пикселя;
   - приведение каждого объекта к общему квадратному холсту;
   - перерисовку объекта в заданном визуальном языке;

   **отличающийся тем, что** для каждого объекта измеряют две независимые
   величины на общем холсте: долю изменения цвета в пределах площади
   объекта и долю изменения формы, равную 1 − IoU силуэта источника
   и силуэта результата, причём обе маски строятся только по
   альфа-каналу (альфа > 16), а яркость на форму не влияет; объект допускается к использованию, только если каждая
   из величин не меньше порогового значения. Для каждого допущенного
   объекта автоматически формируются запись реестра лицензий и перечень
   существенных признаков.

2. Способ по п. 1, отличающийся тем, что пороговое значение равно 35 %.

3. Способ по п. 1, отличающийся тем, что перерисовка включает
   тонирование по яркости в пятиступенчатую шкалу #1a0e04–#e8c87a,
   выделение контура силуэта по альфа-каналу и нанесение двойной
   скруглённой рамки.

4. Способ по п. 1, отличающийся тем, что отклонённые объекты сохраняются
   парами «источник — результат» для визуальной проверки человеком.

5. Способ по п. 1, отличающийся тем, что выполняется на CI-раннере,
   а результаты не публикуются автоматически и передаются на проверку
   в виде артефакта.

6. Способ процедурной трансформации 2D-спрайтов для динамических сред
   (раннеров), **отличающийся тем, что** валидация границ объекта
   производится исключительно сканированием альфа-канала без учёта
   светимости пикселей, с последующей отбраковкой визуальных мутаций,
   чья структурная топология изменилась менее чем на 35 %; при этом
   оригинальные сущности принудительно замещаются семантическими
   Антагонистами, для каждого из которых алгоритмически генерируется
   не менее 12 параметрических и геометрических вариаций для
   интеграции в систему динамических коллизий.
   *(Формулировка оператора, 2026-09-29.)*

7. Способ по п. 6, отличающийся тем, что изменение структурной
   топологии вычисляется как |A XOR B| / |A ∪ B| для бинарных
   альфа-масок источника (A) и результата (B) на общем холсте, а
   смещение внутренних пикселей без изменения внешней границы
   учитывается с коэффициентом 0,1.

8. Способ по п. 6, отличающийся тем, что семантический Антагонист
   выбирается детерминированно по признакам источника (имя файла,
   форма глифа, доминирующий тон) из закрытого перечня восьми страстей
   (чревоугодие, блуд, сребролюбие, гнев, печаль, уныние, тщеславие,
   гордость), получает комплементарную палитру, инвертированную
   фактуру и инвертированный поведенческий признак (пассивное
   препятствие → самонаводящийся объект; награда → опасность,
   выглядящая как награда).

9. Способ по п. 6, отличающийся тем, что 12 вариаций порождаются
   детерминированно из начального значения sha1(источник + путь +
   номер фрагмента): эталон, эрозия, кристаллизация, аморфность,
   симбиот, техно-контур, тёмная материя, рой, эхо, обратная
   гравитация и два гибрида. Каждая вариация имеет собственный хитбокс,
   построенный по альфа-силуэту (выпуклая оболочка, площадь,
   эквивалентный радиус), и собственный идентификатор аналитики.

10. Способ по п. 6, отличающийся тем, что при потере непрозрачных
    пикселей источника без намеренной эрозии обработка объекта
    прекращается с ошибкой `Alpha_Silhouette_Error`.

11. Способ по п. 1, отличающийся тем, что программный код сторонних
    источников оценивается тем же порогом: изменение считается как
    1 − схожесть последовательностей нормализованных токенов (без
    комментариев, с заменой всех идентификаторов единым
    заполнителем), поэтому простое переименование даёт 0 %.

### Замечания ведущего к п. 6 (что уточнено и почему)

- «Сканированием градиента альфа-канала» заменено на «сканированием
  альфа-канала». Граница находится по бинарной маске (альфа > 16), а
  градиент используется только для контура. Так формулировка совпадает
  с кодом, а заявка должна описывать то, что реально работает.
- «Раннер» в п. 6 означает игровой режим динамической среды (в Ludus —
  погружение ROV). CI-раннер (GitHub Actions) описан отдельно, в п. 5.
- Случайные гибриды заменены детерминированными (п. 9): Конституция
  запрещает случайность, а заявке нужна воспроизводимость.

## Почему в формуле два измерения

В первом прогоне метрика считала только долю изменённых пикселей. Тогда
простая перекраска (белый знак «$» стал золотым) получила оценку 100 %,
хотя рисунок не изменился. Поэтому признак «изменение формы» введён как
обязательный. После этого перекраска честно отклоняется: у огненных шаров
и глифов изменение формы составило 3–12 %.

## Ограничения, которые должен знать юрист

1. Порог 35 % — это внутреннее технологическое правило проекта. По
   ГК РФ (ст. 1260, 1270) и по нормам copyright переработка остаётся
   производным произведением при любом проценте изменений. Поэтому
   обязанности по лицензии источника сохраняются: указание автора,
   share-alike для CC-BY-SA, раскрытие исходника для GPL/AGPL. Реестр
   `THIRD_PARTY_NOTICES.md` создаётся для их выполнения.
2. Машинная перерисовка даёт объекты, пригодные для учёта, но не
   готовую игровую графику: тёмные спрайты при тонировании теряются.
   Игровые объекты создаются художниками (людьми или агентами) по
   мотивам сырья, а конвейер фиксирует их отличие от источника.
3. Патентоспособность способа (новизна, изобретательский уровень)
   определяет патентный поверенный. Этот документ — техническое
   описание, а не правовое заключение.
