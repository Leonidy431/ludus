# Технология отбора объектов: «из N лучших — K, без выдумки»

**Статус:** обязательна. CLAUDE.md, ТАБУ №0.07; оператор, 2026-09-30.

**Решение оператора (дословно):** «запиши это технология отбора объектов локаций и пользуйся при заполнении кода локаций сюжетов и так далее».

**Эталон:** 99 объектов Иссык-Куля:
- генератор — `scripts/lake/lake_objects.py`;
- итог — `docs/LAKE_OBJECTS_99.md`;
- пул — `docs/LAKE_OBJECTS_999.json`.

**Где применяется.** Для всякого наполнения, в котором из многих кандидатов выбирают немногих: локации, объекты локаций, сюжетные линии и миссии, NPC, предметы, звуки, дефициты раннера.

---

## 1. Реестр реального

Сначала составляется список **реальных** вещей предмета. Для Иссык-Куля это виды рыб по ихтиологии озера, донная жизнь, растения, геология шельфа, находки затопленных поселений, явления воды, следы людей, птицы.

- У каждой вещи есть основание: источник, наблюдение, физика, канон.
- Для содержания игры основанием служит патристический канон `data/patristic-canon.json` (ТАБУ №0.35 п. 18).
- Вещь без основания в реестр не входит.

## 2. Честный пул

Пул — это сочетания реальной вещи с её **состояниями** и **поясом места**. Для озера это пояс глубины, для сюжета — акт, для локации — время суток или сезон.

- Каждое сочетание должно быть правдоподобным: рыба вне своего диапазона глубин в пул не попадает.
- **Число пула не подгоняется.** Если просили 999, а честно получилось 529, записывается 529 и прямо объясняется почему.
- Добивать пул выдумкой запрещено (табу «не симулировать», ТАБУ №0.6).

## 3. Оценка по открытым критериям

Каждый кандидат получает баллы 0–10 по пяти критериям. Критерии и веса записаны в коде, а не держатся в голове:

| Критерий | Вопрос |
|---|---|
| правда | Это действительно есть в мире игры (озеро, эпоха, канон)? |
| учительная связь | Несёт ли объект ФОРМУ → ДЕЙСТВИЕ → ЦЕЛЬ: границу, ритм, терпение, выбор? |
| читаемость | Прочтёт ли игрок его в шлеме на рабочей дистанции? |
| новизна | Нет ли уже такого в игре? |
| безопасность | Святое не становится находкой, лутом, врагом или оружием; страсть не выдаётся за награду без признака (ТАБУ №0.2, №0.35 п. 6) |

- Бонусы за состояние и поясные поправки записываются в коде явно.
- Порядок **детерминирован**: одинаковые баллы разбираются по id, случайности нет (ТАБУ №0.35 п. 15).

## 4. Отбор с разнообразием

Берутся K лучших по сумме баллов с двумя ограничениями:
- **не больше двух состояний на одну вещь**, иначе 99 объектов превратятся в 99 рыб;
- **минимум по каждой категории**, чтобы у места были все стороны: жизнь, материя, свет, человек.

## 5. Изготовление

Отобранное доводится до игры полностью, а не остаётся списком:
1. **данные** — `public/ludus/data/<набор>.json` с `flags`, для святого и наблюдаемого это `noLoot` и `noInteract`;
2. **показ** в игре с условием появления: пояс, акт, врата;
3. **объём для Meta** — прокси `.glb` из примитивов в `public/vr/models/<набор>/` с `lod: proxy` (ТАБУ №0.32);
4. **тесты**: объект появляется только в своём поясе, флаги на месте, генератор даёт одно и то же при повторе;
5. **снимок глазами**. Подпись без видимого объекта — брак. Эталон: первый снимок озера показал подпись из шести объектов над пустым дном, объекты увеличили.

## 6. Документ для оператора

Каждый отбор оставляет таблицу `docs/<НАБОР>_K.md` и пул `docs/<НАБОР>_N.json`. В них записаны:
- реальный размер пула и почему он такой;
- критерии и минимум по категориям;
- что осталось проверить специалисту (ихтиологу, историку, богослову) до релиза.

## 7. Спорное наполнение

Если объект касается богословия или образа святого, отбор не решает его сам. Такой объект идёт хору 12 редакторов-гуру (ТАБУ №0.37) с записью «предубеждение / контраргумент / почему».

---

**Коротко:** реестр реального → честный пул без подгонки → открытые баллы → отбор с разнообразием → данные + показ + объём + тесты + снимок → таблица для оператора.
