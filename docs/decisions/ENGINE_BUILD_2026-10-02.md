# Решение: движок шлема без лишних библиотек — одна сборка из честного пула по 48 параметрам (2026-10-02)

Поручение оператора (дословно): «godot возможно как то в бинарник без лишних библиотек сконвертировать потом? поищи единственное решение из 888 по 48 параметрам из имеющихся».

**Конституция:** ФОРМА (что шлем может нести: собственные байты движка) → ДЕЙСТВИЕ (каждый способ собрать движок оценивается одними открытыми правилами) → ЦЕЛЬ (место под голоса учения без тяжелеющего APK).

## Пул и выбор

Команда: `python3 scripts/decisions/engine_build_choice.py`; в CI — `--check`.

- **Пул — 1 300 вариантов, а не 888** (ТАБУ №0.07 п. 2: число не подгоняется). Его дают девять измерений:
  - готовый или свой шаблон;
  - оптимизация `speed` / `size` / `size_extra`;
  - LTO нет / `thin` / `full`;
  - профиль классов нет / по проекту / ручной;
  - текстовый сервер `adv` (ICU) / `fb`;
  - модули все / без неиспользуемых / минимум;
  - где собирать: в каждом задании или в кэше;
  - библиотеки в APK без сжатия / сжаты;
  - плагин вендоров Meta оставить / убрать.

  У готового шаблона измерения сборки не меняются, поэтому у него 4 варианта, у своего — 1 296.
- **Отсечено жёсткими ограничениями 1 010:**
  - 650 — без плагина вендоров Meta: шаг CI «Check the APK is a Quest OpenXR app» не находит записей `com.oculus`;
  - 324 — сборка движка в каждом задании `android`: больше 45 минут;
  - 36 — минимум модулей без профиля классов: `Image.load` остаётся без своего формата.
- **Осталось 290.** Каждый вариант оценён по 48 параметрам `scripts/decisions/engine-params-48.json`. Наибольшее возможное — 178.

**Выбор:** собственный шаблон экспорта Godot 4.7.1 для Android, отладочный и выпускной, собранный SCons с:
- `optimize=size`;
- `lto=thin`;
- `build_profile=` с отключёнными неиспользуемыми классами;
- отключёнными модулями, которые игра не вызывает (сеть, навигация, CSG, GridMap, видео, шумы);
- полным текстовым сервером.

Собирается отдельным заданием и кэшируется по хэшу «версия движка + профиль + флаги». Задание `android` берёт готовый кэш, а если его нет — стоковый шаблон с заметкой.

## Почему не проще

1. **Выпускной готовый шаблон.**
   - Предубеждение: «возьми release — и всё».
   - Контраргумент: он легче всего на 5,1 МБ и убирает проверочный вход оператора (`OS.is_debug_build()`), без которого 12 сюжетов в шлеме не проверить.
   - Почему: выпускной нужен магазину, а для теста нужна отладочная сборка той же урезки (e05, e37).
2. **Сжать библиотеки в APK.**
   - Предубеждение: «−48 МБ одной галочкой».
   - Контраргумент: Android распакует их при установке, и вес переедет из APK на диск шлема; это обход бюджета, а не экономия (e02, e19). К тому же нужна сборка Gradle.
   - Почему: библиотеки без сжатия, урезается сам движок.
3. **`text_server_fb`.**
   - Предубеждение: «ICU не нужен, текст простой».
   - Контраргумент: сегодня да, но церковнославянские надстрочные знаки без сложной вёрстки съедут.
   - Почему: `adv` остаётся; если замер покажет, что ICU — главный вес, вопрос вернётся хору с числом.
4. **Размер.**
   - Предубеждение: «напиши, сколько выйдет».
   - Контраргумент: число без замера не пишется (ТАБУ №0.011 п. 6).
   - Почему: правила ранжируют варианты по тому, что они убирают, а размер своего шаблона снимается после первой сборки (HLD, фаза E5).
5. **Попутная выгода.**
   - Предубеждение: «свой движок — лишняя работа».
   - Контраргумент: свой шаблон собирается с отдельным файлом символов. Тогда падение потока звука в CI (2026-10-02, signal 11, кадры рядом с `AudioServer`) читается по именам функций, а не по адресам (e30, e31).
   - Почему: свой шаблон.

Скептик: правила и веса писал тот же голос, что считал. Проверить может любой: изменить вес или правило в файлах и запустить команду.
